# Монетизация

MVP: только один видимый адаптивный баннер на обзорном экране после полезной информации. Нет рекламы при запуске, после подтверждения, в формах, сверке, настройках, импорте/экспорте или уведомлениях. Базовый учёт и доступ к данным бесплатны. Подписка и платежи не реализуются до решения владельца о магазине и юридической модели.

Провайдер: Yandex Mobile Ads SDK, test/no-op/production реализации. Финансовые суммы, даты графика/выплат, работодатели и резервные копии не поступают провайдеру или аналитике. Production блоки предоставляются владельцем; тестовые IDs не подменяют production.

## Модель с предположениями

Месячный доход ≈ DAU × среднее число допустимых показов в день × fill rate × eCPM / 1000 × число дней.

Иллюстрация, не прогноз: DAU=1000, 1 показ/день, fill=0,7, eCPM=50 ₽, 30 дней дают 1050 ₽ до расходов/налогов. Эти числа не подтверждены рекламным кабинетом. Нельзя оценить пассивный доход без статистики, стоимости привлечения и поддержки.

Нужны данные по D1/D7/D30, первой/третьей смене и использованию сверки, DAU/MAU, рекламным запросам/показам, eCPM/ARPDAU, ошибкам/ANR. До появления проверенного механизма согласий внешняя продуктовая аналитика не включается. Локальные агрегаты можно вычислять по собственным записям; установки и доход проверяются только по статистике магазинов/рекламного кабинета.

Критерий решения: сравнить удержание до/после рекламы на закрытой beta. Реального дохода и измерений удержания пока нет.

## Реализация

Yandex SDK 8.6.0, проверен по официальным Maven metadata и примеру yandexmobile/yandex-ads-sdk-android. SDK не инициализируется автоматически. По умолчанию пользователь не дал согласия; переключатель в настройках показывает объяснение и ссылку на политику. В debug используется только demo-banner-yandex. В release пустой YANDEX_BANNER_ID означает no-op; demo ID в production provider запрещён. Полный отказ от рекламы не ограничивает учёт.

Удалённое отключение: config/ads.json в защищённом main. Значение enabled=false по умолчанию; запрос только после согласия и при production ID, отказ при сетевой ошибке. Проверка производится при входе на экран, поэтому уже открытое объявление может оставаться до ухода с него. Новая версия APK для выключения не нужна; настройку меняют через PR.

Только «Сегодня», в конце страницы, не в формах и не на экране сверки. После сохранения смены размещение подавляется до смены вкладки. Нет своих таймеров показов. Native BannerAdView уничтожается при уходе с экрана, отзыве согласия и изменении размера.
