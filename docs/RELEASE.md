# Выпуск

## Подготовка

Основная ветка main защищена PR, strict required checks (Android build, lint and tests; Wrapper integrity; Dependency review), линейной историей и запретом force push/delete. Защита применяется к администраторам. Обязательных внешних approvals нет. CI работает с read-token; нет pull_request_target и secrets в fork PR.

Workflow Release preparation сначала выполняет device tests API 26/36, затем release unit tests, Lint, сборку неподписанных APK/AAB. Метаданные включают версию, UTC-дату, commit SHA и SHA-256. CHANGELOG включён в комплект. Скрипт проверяет структуру архивов и отсутствие файлов ключей, локальной конфигурации и базы. Для каждого APK/AAB workflow создаёт GitHub artifact attestation. Проверка происхождения: `gh attestation verify ФАЙЛ -R StanleyLl0yd/it-adds-up`. Неподписанные артефакты предназначены для проверки и последующей подписи; их нельзя выдавать за опубликованный production-релиз.

Оба магазина получают тот же native Android-проект без обязательных Google Play Services. Финальные допустимые форматы и требования кабинета RuStore/Google Play проверяются перед каждой отправкой. Публикация автоматикой не выполняется.

## Production-подпись

Ключи создаёт и хранит владелец. Не генерировать фиктивные production-ключи и не подписывать production debug-ключом. Защищённое environment production требует подтверждения StanleyLl0yd и разрешает только protected branches.

После юридической/продуктовой готовности владелец добавляет environment secrets:

- RELEASE_STORE_BASE64 — base64 существующего keystore;
- RELEASE_STORE_PASSWORD;
- RELEASE_KEY_ALIAS;
- RELEASE_KEY_PASSWORD.

Workflow подписывает только main при явном signed=true и после unsigned/device-проверок. Keystore временно размещается в runner.temp и удаляется trap. Не включается в артефакты. Подпись APK проверяется apksigner. Секреты не передаются PR-коду.

## Перед магазином

1. Все required checks и device tests зелёные; подтвердить main SHA после merge.
2. Проверить портрет/альбом, увеличенный шрифт, TalkBack, маленький экран, offline, напоминания и полный путь backup → erase → restore на физическом устройстве.
3. Проверить release APK/AAB и merged manifest, состав зависимостей, отсутствие секретов/данных и debug signing.
4. Утвердить имя/лицензию, юридические сведения оператора, контакт поддержки, доступную политику и анкеты данных/рекламы по фактической сборке.
5. Для рекламной версии предоставить production ID, проверить согласия и актуальные правила SDK/магазина. Demo ID никогда не используется в production provider.
6. Закрытая beta и обратная связь реальных пользователей. Статистика удержания и дохода ещё не получена.
7. Владелец отправляет подписанный комплект в магазин. Публикация подтверждается только решением магазина.

## Известные границы alpha

Один профиль/смена на дату, RUB, один редактируемый неоплачиваемый перерыв в UI (движок допускает несколько), ночное окно 22–06, начало периода/день выплаты 1–28. Изменение графика перестраивает несохранённые плановые дни; сохранённые смены имеют свои условия. История не изменяется при добавлении новой ставки. Напоминания неточные и могут задерживаться Android. Потерянный пароль резервной копии восстановить нельзя. Без физического QA/beta готовность 1.0 не заявляется.
